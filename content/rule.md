# 구조 규칙

- H2(`##`)는 페이지 구분
- 기술 스택은 각 프로젝트의 핵심 기술만 표시
- project는 앞 숫자 라벨링이 되어있는 파일을 의미, 숫자는 프로젝트의 순서를 의미함
- layout의 프로젝트는 프로젝트 파일들을 참조
- 프로젝트가 아닌 장은 숫자 접두사 없이 이름으로 파일을 만듦. layout에서 함께 참조

# 검토 항목

검토 요청 시 아래 항목의 통과 여부를 항목별 결과 표로 제공한다.

- —, 중단점, 문장 강조 따옴표, 이모지 등은 사용하지 않음
- 그림과 표에 딸린 설명은 개조식으로 씀. 항목으로 끊고 명사형으로 맺음
- 개조식의 목적은 문장 완결성이 아닌 한눈에 읽히는 정보 압축. 자연스러운 문장으로 늘리지 않음
- 항목당 사실 또는 판단 1개만 유지. 주어, 조사, 반복 맥락, 자명한 서술어는 의미 손실이 없으면 삭제
- 명사형 종결만으로는 개조식이 아님. 해도, 하면, 이라, 되어, 지만 같은 연결어미와 군더더기 조사까지 걷어내고 명사구로 끊음
- 예: `탈락 요청은 즉시 반려. 뒤로 흘려보내지 않음` → `탈락 요청 즉시 반려`
- 부사는 빼보고 판단. 빼도 뜻이 같으면 삭제, 빼면 주장이 약해지거나 사실이 사라지면 유지
- 수치를 옆에 적었으면 대폭, 크게 같은 강조 부사는 쓰지 않음. 수치가 이미 말하고 있음
- 서술식 유지 여부는 절 이름이 아니라 논지 유무로 판단. 개요, 트레이드오프, 결론이 대체로 여기 해당. 논지가 없으면 개조식을 기본값으로 적용
- 논지는 반박 가능한 주장을 말함. 확인하면 끝나는 사실과 구분. A가 아니라 B다, ~를 감수한 선택이다 같은 판단이 논지
- 논지 있는 문단에 사실 나열이 섞이면 나열은 항목으로 빼고 논지만 문장으로 남김. 논지가 나열에 묻히지 않게 함
- 서술식의 짝은 개조식임. 단답식, 단답형은 시험 문제 유형 용어라 문서 서술 방식에는 쓰지 않음
