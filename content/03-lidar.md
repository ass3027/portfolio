# 김포공항 LiDAR 기반 실시간 여객 흐름과 대기시간 예측

- **구분**: 스피어에이엑스, 2025.09 ~ 2026.02

---

## 핵심 개선과 성과

### 기술 스택

`Spring Boot` `gRPC / C++` `Prometheus` `Grafana`

### 개요

LiDAR 데이터를 기반으로 **실시간 여객 위치와 인원 수, 예상 대기시간**을 제공하는 프로젝트다. 합류 당시 기본 통계만으로는 **대기시간 예측 성능을 평가하기 어려워** 고객사 기준에 맞춘 개선이 지연되고 있었다. C++ 데이터 중계 서버의 **간헐적 종료**로 운영 안정성도 낮았다.

### 실시간 메트릭 수집과 분석 흐름

```
LiDAR 데이터 서버
        │ gRPC
        ▼
C++ 데이터 중계 서버
        │ REST API
        ▼
Backend
        │
        ▼
메트릭 선별과 산출
        │
        ├── 메트릭 노출 ──► Prometheus ──► Grafana
        │
        └── 분석 데이터 기록 ──► CSV 로깅 ──► Python 분석 ──► 결과 리포트
```

#### 1. 실시간 메트릭 분석 환경 구축

- **문제**: 예측 성능 평가와 개선 지점 파악에 한계.
- **해결**: 핵심 메트릭 정의/수집 범위 확장. Prometheus + Grafana 실시간 시각화, Python CSV 리포트 자동화.
- **성과**: 예측 성능 분석 파이프라인 구축. 분석과 개선 시간 **80% 단축**.

#### 2. C++ 데이터 중계 서버 메모리 누수 해결

- **문제**: C++ 데이터 중계 서버의 프로세스 메모리 누수와 간헐적 종료.
- **해결**: Visual Studio 디버깅 + 누수 지점 확인. Backend에 메모리 모니터링 및 이상 시 자동 재시작 기능 추가.
- **성과**: 프로세스 메모리 안정화, **간헐적 종료 해소**.

#### 3. 분산 비즈니스 로직 통합과 객체 수명 정리

- **문제**: service 계층과 FE에 흩어진 비즈니스 로직, 해제 시점 없는 객체 누적.
- **해결**: 로직을 도메인 엔티티로 이동. FE/BE 중복 데이터 처리는 목적에 맞는 신규 클래스로 통합, 누적 객체 TTL 적용.
- **성과**: 메모리 **70% 감소**, 코드량 **50% 감소**.
