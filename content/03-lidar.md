# 김포공항 LiDAR 기반 실시간 여객 흐름과 대기시간 예측

- **구분**: 스피어에이엑스, 2025.09 ~ 2026.02

---

## 프로젝트 요약

### 개요

LiDAR 데이터를 기반으로 실시간 여객 위치와 인원 수, 예상 대기시간을 제공하는 프로젝트다.

합류 당시 기본 통계만으로는 대기시간 예측 성능을 평가하기 어려워 고객사 기준에 맞춘 개선이 지연되고 있었다.

또한 C++ 데이터 중계 서버의 간헐적 종료로 운영 안정성이 낮았고, 대기시간과 혼잡도 로직이 분산돼 유지보수도 어려웠다.

### 핵심 목표

- **실시간 메트릭 분석 환경 구축**: 예측 성능 평가 기반 확보, 분석과 개선 시간 **80% 단축**
- **C++ 데이터 중계 서버 안정성 확보**: 간헐적 종료 **해소**
- **분산 로직 공통 모듈 통합**: 메모리 **70%↓**, 코드량 **50%↓**

### 기술 스택

`Spring Boot` `gRPC / C++` `Prometheus / Grafana`

### 실시간 메트릭 수집과 분석 흐름

```
LiDAR 데이터 서버
        │ gRPC
        ▼
C++ 데이터 중계 서버
        │ REST API
        ▼
Backend
        │
        ▼
메트릭 선별과 산출
        │
        ├── 메트릭 노출 ──► Prometheus ──► Grafana
        │
        └── 분석 데이터 기록 ──► CSV 로깅 ──► Python 분석 ──► 결과 리포트
```

### 핵심 개선과 성과

#### 1. 실시간 메트릭 분석 환경 구축

- **문제**: 기본 통계만으로 예측 성능 평가와 개선 지점 파악에 한계.
- **해결**: 핵심 메트릭 정의와 수집 범위 확장. Prometheus와 Grafana 실시간 시각화, Python CSV 리포트 자동화.
- **성과**: 예측 성능 분석 파이프라인 구축. 분석과 개선 시간 **80% 단축**.

#### 2. C++ 데이터 중계 서버 메모리 누수 해결

- **문제**: 최초 gRPC 수신 데이터에 포함된 객체 좌표 데이터의 해제 누락으로 프로세스 메모리 누적과 간헐적 종료 발생.
- **해결**: 객체 좌표 데이터 처리 후 메모리 해제 적용. Backend 프로세스 메모리 모니터링으로 안정화 확인.
- **성과**: 메모리 누적과 **간헐적 종료 해소**.

#### 3. 혼잡도와 대기시간 로직 공통 모듈 통합

- **문제**: 대기시간 기반 혼잡도와 세부 처리 로직의 분산 및 중복에 따른 유지보수성 저하.
- **해결**: 분산 로직을 Backend 공통 모듈로 통합.
- **성과**: 메모리 **70% 감소**, 코드량 **50% 감소**.
