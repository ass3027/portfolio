### 도식의 시각적 위계

기술 페이지 제목 아래에 문제와 설계 판단을 한두 줄로 표시합니다. 측정값이 있는 페이지에는 해석에 필요한 조건을 함께 표시합니다.

구성 요소 사이의 화살표는 호출·접근 주체에서 대상으로 향합니다. 요청과 응답은 같은 호출선에 표시하고, 절차를 설명하는 도식에는 단계 순서를 표시합니다.

페이지 제목이 설명하는 설계 판단을 기준으로 핵심 요소에 크기, 배치, 대비를 집중합니다. 입력과 실행 단계는 중간 강도로 표시하고, 관측 조건·보조 경로·실험 환경은 같은 흐름 안에서 구분합니다.

도식의 아이콘은 서버, 저장소, 처리 태스크, 사용자 승인 등 구성 요소의 역할을 표시합니다. 동일한 역할에는 같은 선 아이콘을 사용하고, 수치 비교에는 측정 항목 단위로 표시합니다.

AWS 서비스에는 [AWS Architecture Icons](https://aws.amazon.com/architecture/icons/)의 공식 아이콘을 사용합니다.

| 쪽 | 가장 먼저 볼 요소 | 이어서 볼 요소 |
|---|---|---|
| 02 | 주요 실행 서비스 RPCN, FastAPI BE, save-admin | 사용자 화면, 저장소, 호출·접근 경로 |
| 03 | TLS 소켓 위에서 동작하는 Python RPCN 클라이언트 | 서버 버전 확인, 로그인 패킷, Protobuf 조회 |
| 04 | EventConsumer에서 방 관측과 세이브 이벤트 결합 | RPCN과 save-admin 조회, 공유 PostgreSQL의 이벤트 적재와 선점, 전적 저장 |
| 05 | save-admin의 게임 세이브 파싱과 API | RPCN DB와 세이브 파일의 역할, 관리자 수정과 복구 |
| 06 | CloudFront에서 ECS Fargate로 이어지는 초기 서비스 경로 | RDS와 ElastiCache, ECR 배포, Lightsail 전환 이유 |
| 07 | MySQL의 최종 정합성 방어 | Redis 입장 제어와 원자 선점, 동일 좌석 실험 결과 |
| 08 | 각 실험의 대표 OFF와 ON 측정값 | 실험별 범위와 보조 지표 |
| 09 | 이슈 발행과 구현 착수의 두 승인 지점 | API 오류 응답 표준화 GitLab 이슈 사례 |
| 10 | 실제 큐 조회 요청 방향 | SQL 근거, 기존 데이터 이동 표현 |
