# AI 활용: 코드 리뷰 자동화와 배포 검증 스킬 설계

- 적용 대상: 사내 프로젝트 리뷰와 Tag2Now 배포 호환성 검증 설계
- 기술 스택: `AI Agent` `GitLab REST API` `WebHook` `KakaoWork` `Docker Compose`

## 핵심 개선과 성과: 사내 코드 리뷰와 이슈 발행

### 덱 표시

- AI 에이전트가 `project-review` 스킬로 저장소 분석부터 승인된 GitLab 이슈 발행까지 실행합니다.

| 위치 | 표시 문구 |
|---|---|
| 왼쪽 상위 스킬 | `project-review` · 리뷰와 이슈 발행 조율 |
| 왼쪽 하위 스킬 | `review-analyze-metadata` · 기술 스택, 빌드 명령, 이슈 트래커 감지 |
| 왼쪽 하위 스킬 | `review-organize-tasks` · 발견 사항 분류와 이슈 초안 작성 |
| 왼쪽 하위 스킬 | `review-publish-issues` · GitLab REST API로 승인된 이슈 발행 |
| 왼쪽 참조 문서 | `references/checklist.md` · 공통 기준과 기술 스택별 검수 항목 |
| 오른쪽 실행 흐름 | 저장소 분석 → 에이전트 코드 리뷰 → 이슈 초안 → 사람의 발행 승인 → GitLab 등록 |
| 리뷰 범위와 근거 | 품질, 보안, 버그, 빌드 점검 / 파일과 라인 근거 기록 |
| 초안 산출물 | 우선순위와 근거를 담은 초안 |
| 발행 승인 | 사람이 발행할 이슈 선택 |
| 발행 이후 | KakaoWork 자동 알림 |
| 오른쪽 하단 후속 개발 | 이슈 회수 → 구현 계획 → 사람의 착수 승인 → 구현과 검증 |
| 왼쪽 하단 실제 이슈 | API 오류 응답 표준화 제안 |
| 이슈 근거 | 인증 실패, 전역 예외, 컨트롤러에서 오류 응답 형식 3종 확인 |
| 호환성 조건 | 프런트엔드 호환을 위해 `message` 필드 유지 제안 |

### 문제

- 리뷰 결과의 수동 이슈 등록과 팀 공유
- 분석 결과와 후속 개발 작업의 분리
- 세션 종료에 따른 작업 근거와 진행 상태 유실

### 해결

| 단계 | AI와 연동 도구 | 사람의 판단 |
|---|---|---|
| 코드 리뷰 | 공통 기준과 스택별 체크리스트 적용, 품질·보안·버그·빌드 점검, 파일·라인 근거 기록 | 지적의 타당성과 우선순위 |
| 이슈 초안 | 발견 사항 분류와 이슈 본문 작성 | 수정 대상과 제외 항목 |
| 이슈 발행 | GitLab REST API 호출 | 발행 대상 승인 |
| 팀 공유 | GitLab WebHook과 KakaoWork 연동 | 공유된 결과 확인 |
| 작업 착수 | 이슈 회수와 구현 계획 작성 | 범위와 계획 승인 |
| 작업 종료 | 구현, 검증 결과와 작업 목록 갱신 | 목표 충족 여부 검토 |

### 성과

- 리뷰 근거에서 이슈와 후속 작업으로 이어지는 흐름 구성
- 이슈 등록과 팀 공유의 반복 작업 자동화
- 작업 목록과 Git 이력을 통한 세션 간 상태 확인

### 설계 판단

분석과 초안 작성은 자동화하고, 이슈 발행과 작업 착수에는 사람의 승인을 두었습니다. 승인 경계는 제안이 외부 상태와 실제 코드 변경으로 이어지는 시점에 배치했습니다.

### 실행 상태의 기준

- 작업 범위: 승인된 계획
- 진행 상태: 저장소의 작업 목록
- 완료 근거: 검증 결과와 변경 이력

## 핵심 개선과 성과: 서비스 배포 호환성 검증 스킬

### 덱 표시

- 설계안 · 스킬 구현과 버전 조합 검증 예정
- save-admin과 백엔드가 따로 배포되므로, 한쪽만 새 버전인 상태에서 전적 조회 계약을 검증하도록 설계했습니다.

| 검증 대상 | 기대 결과 |
|---|---|
| save-admin 선배포 · 신규 save-admin과 기존 백엔드 | 캐릭터 계급 필드 추가 후에도 기존 전적 조회 성공 |
| 백엔드 선배포 · 기존 save-admin과 신규 백엔드 | 계급 정보가 없어도 전적 조회 성공, 응답의 계급은 null |
| 사람이 정할 입력 | 서비스별 버전, 재생할 세이브, API 기대 결과 |
| 에이전트 스킬의 공통 절차 | 변경 이력 대조 → 격리된 Docker Compose 실행 → 세이브 재생 → 실제 API 응답 대조 → 실패 조합과 로그 기록 |
| 재사용 확인 계획 | 다음 프로젝트에서 버전과 테스트 입력, API 기대 결과를 바꿔 같은 스킬 실행 |

### 문제

- 두 저장소의 독립 배포로 인한 혼합 버전 구간
- 전적 응답의 캐릭터 계급 필드 추가에 따른 호환성 확인

### 해결

- 기존 로컬 리플레이를 기반으로 양쪽 배포 순서를 각각 실행하는 스킬 설계
- 사람이 지정한 기대 결과를 기준으로 실제 전적 API 응답 검증
- 실패 시 버전 조합, 예상과 실제 응답의 차이, 서비스 로그 기록

### 성과

- 혼합 버전 검증 대상과 기대 결과 정의
- 스킬 구현과 두 버전 조합의 실행 검증 예정
- 다음 프로젝트에 동일 절차 적용 예정
