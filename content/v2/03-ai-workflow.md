# AI 활용: 업무 자동화와 산출물 검증

- 적용 대상: 사내 프로젝트 리뷰와 Tag2Now 아키텍처 설명
- 기술 스택: `AI Agent` `GitLab REST API` `WebHook` `KakaoWork` `Git`

## 핵심 개선과 성과: 근거 수집부터 승인된 변경까지 연결

### 문제

- 리뷰 결과의 수동 이슈 등록과 팀 공유
- 분석 결과와 후속 개발 작업의 분리
- 세션 종료에 따른 작업 근거와 진행 상태 유실

### 해결

| 단계 | AI와 연동 도구 | 사람의 판단 |
|---|---|---|
| 코드 리뷰 | 품질, 보안, 버그, 빌드 점검과 파일 및 라인 근거 수집 | 지적의 타당성과 우선순위 |
| 이슈 초안 | 발견 사항 분류와 이슈 본문 작성 | 수정 대상과 제외 항목 |
| 이슈 발행 | GitLab REST API 호출 | 발행 대상 승인 |
| 팀 공유 | GitLab WebHook과 KakaoWork 연동 | 공유된 결과 확인 |
| 작업 착수 | 이슈 회수와 구현 계획 작성 | 범위와 계획 승인 |
| 작업 종료 | 구현, 검증 결과와 작업 목록 갱신 | 목표 충족 여부 검토 |

### 성과

- 리뷰 근거에서 이슈와 후속 작업으로 이어지는 흐름 구성
- 이슈 등록과 팀 공유의 반복 작업 자동화
- 작업 목록과 Git 이력을 통한 세션 간 상태 확인

### 설계 판단

분석과 초안 작성은 자동화하고, 이슈 발행과 작업 착수에는 사람의 승인을 두었습니다. 승인 경계는 제안이 외부 상태와 실제 코드 변경으로 이어지는 시점에 배치했습니다.

### 실행 상태의 기준

- 작업 범위: 승인된 계획
- 진행 상태: 저장소의 작업 목록
- 완료 근거: 검증 결과와 변경 이력

## 핵심 개선과 성과: AI 생성 설명과 실제 구현 대조

### 적용 사례

- 대상: Tag2Now 포트폴리오 아키텍처 설계도
- 검토 범위: 서비스 관계와 전적 수집 구조

### 문제

- 데이터 이동 방향과 호출 주체 표현의 혼선
- PostgreSQL 큐의 역할을 드러내지 못한 단순 구성도
- 전적 처리도에서 원본 세이브 출처 생략
- 기존 포트폴리오의 강조점과 이미지 구성 불일치

### 해결

| 확인 대상 | 대조 근거 | 반영 내용 |
|---|---|---|
| 화살표 의미 | 호출과 응답의 구분 | 주체 → 접근 대상 통일 |
| 이벤트 소비 | EventConsumer의 큐 조회 코드 | 소비자에서 큐로 향하는 접근선 |
| 세이브 원본 | save-admin의 DB 및 파일 접근 | 메타데이터 조회와 TUS 읽기 분리 |
| 실행 경계 | FastAPI lifespan의 태스크 생성 | BE 내부 태스크와 저장소 구분 |
| 처리 순서 | 수집과 소비의 독립 루프 | A/B/C별 번호와 독립 실행 명시 |

### 성과

- 서비스 관계도와 전적 처리도의 분리
- 도표의 요청 방향과 실제 호출 주체 일치
- 원본 데이터 접근과 영속 큐 역할의 명시

### 검토 기준

설명과 도표도 구현을 대조해야 하는 산출물로 다뤘습니다. AI가 제시한 구성은 표현의 완성도와 함께 호출 주체, 저장소 역할, 실행 경계의 일치 여부를 확인했습니다.
