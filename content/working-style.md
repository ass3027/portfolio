# 일하는 방식

## 일하는 방식

### 측정한 뒤에 고친다

- 추측성 최적화 배제. 병목으로 측정된 지점에만 착수하도록 트리거 조건 명문화
- 증상이 아니라 원인 추적. 1,000 동시 연결 거부의 진짜 원인이 애플리케이션이 아닌 Docker NAT 포화임을 격리 실험으로 규명
- 설계 결정은 Before/After 실측으로 검증. 선점을 꺼도 정확성이 동일하다는 불리한 결과도 그대로 기록

### AI는 통제하며 쓴다

- 계획, 테스트 유효성, 커밋 승인 3개 지점에 사람 게이트
- AI가 구현한 저수준 통신 코드도 단위 테스트와 통합 테스트로 동작 실측 검증
- 생성물을 그대로 두지 않음. 명세와 구조는 직접 재작성

### 배포가 끝이 아니다

- 실서비스 운영. 오픈 카카오톡방 실사용자 제보로 오류 수정과 기능 개선 반복
- 비용과 트래픽을 재보고 규모에 맞게 인프라 다운스케일 판단
- 저장소는 데이터 특성에 맞게 선택. 한 서비스에서 Redis, PostgreSQL, DynamoDB 병행 운용
