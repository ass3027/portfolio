# AI 협업 워크플로우: 승인과 검증 중심의 개선 루프

- **구분**: 개인 프로젝트, 2026

---

## 프로젝트 요약

### 개요

AI 에이전트를 단순한 코드 생성 도구가 아니라, 명확한 책임 경계와 승인 게이트, 검증 규칙을 갖춘 협업 시스템으로 설계한 프로젝트다.

코드 리뷰부터 이슈 발행, 팀 알림, 후속 작업 착수까지를 하나의 폐쇄형 개선 루프로 연결했다. 되돌리기 어려운 변경은 사람의 승인 뒤에만 실행하고, 작업 목록과 테스트, Git 이력으로 진행 상태와 결과를 추적한다.

### 핵심 목표

- **코드 리뷰 개선 루프 구축**: 분석, 이슈 발행, 팀 알림, 작업 목록화, 착수 단계 연결
- **승인 게이트 적용**: 이슈 발행과 작업 착수 전 사람의 검토와 승인 적용
- **세션 간 작업 상태 유지**: 작업 목록, Git 이력, Phase 결과 문서를 단일 기준으로 운영
- **검증 규칙 명문화**: 변경 근거, 테스트 범위, 커밋 단위 기준 문서화

### 기술 스택

`Claude Code` `GitLab REST API` `GitLab Webhook` `KakaoWork` `Git` `Markdown`

## 시스템 아키텍처

### 사내 프로젝트 개선 파이프라인

```
프로젝트
   │
   ▼
문제점 분석
   │
   ├── 승인 ──► 이슈 발행 ──► 카카오워크 알림
   │                              │
   │                              ▼
   │                         이슈 작업 목록화
   │                              │
   └──────────────── 승인 ◄───────┤
                                  ▼
                             작업 착수
                                  │
                                  └──── 개선 결과 환류 ────► 문제점 분석
```

- **문제점 분석**: 품질, 보안, 버그, 빌드 4개 영역 점검
- **이슈 발행**: 파일과 라인 근거 기반 이슈 초안 생성, 승인 항목만 GitLab REST API 발행
- **팀 알림**: GitLab 웹훅과 카카오워크 채널 연동
- **후속 작업화**: 이슈 조회, 심각도 기준 작업 목록화
- **작업 착수**: 승인 후 우선순위 기반 구현과 검증, 분석 단계 환류

### 인간과 AI 협업 실행 사이클

```
설계·계획 문서
      │ 작업 추출
      ▼
Task_Checklist: 단일 기준
      │
      ▼
다음 작업 선정 → 계획 → 승인 → 구현과 테스트 → 테스트 검토 → 커밋
                                      │                         │
                                      └────── Phase 결과 문서 ◄─┘
                                                        │
                                                        └── 체크리스트 갱신
```

## 아키텍처 결정

### 승인 게이트와 자동화 경계

| 단계 | 자동화 역할 | 사람의 역할 |
|---|---|---|
| 분석 | 코드베이스 점검, 근거 수집, 이슈 초안 작성 | 결과와 우선순위 검토 |
| 이슈 발행 | 승인 항목의 GitLab REST API 발행 | 발행 대상 승인 |
| 작업 착수 | 계획, 구현, 테스트 제안과 실행 | 작업 범위와 구현 계획 승인 |
| 커밋 | 변경 요약과 메시지 초안 작성 | 커밋 실행 승인 |

AI가 분석과 반복 작업을, 외부 상태 변경과 되돌리기 어려운 작업은 사람이 승인한다. 속도를 위해 통제를 포기하지 않고, 승인 대기로 인해 분석과 준비 작업까지 멈추지 않도록 경계를 나눴다.

### 작업 상태의 단일 기준

| 기준 | 역할 |
|---|---|
| `Task_Checklist` | 다음 작업 선정과 완료 상태 관리 |
| Git 이력 | 실제 변경과 커밋 단위 추적 |
| Phase 결과 문서 | 목표 충족 여부 검토와 작업 마감 |
| 협업 규율 문서 | 세션 간 계획, 승인, 검증 규칙 유지 |

휘발성 작업 목록 대신 저장소 안의 문서와 Git 이력으로 상태를 관리했다. 새 세션에서도 이전 결정의 근거와 다음 작업을 다시 확인할 수 있다.

## 핵심 기술적 도전

### 1. 코드 리뷰를 후속 작업까지 연결하는 폐쇄형 개선 루프

- **문제**: 코드 리뷰 결과가 이슈, 팀 알림, 실제 수정 작업으로 이어지지 않으면 분석 결과가 일회성 보고로 끝남.
- **성과**: 분석, 승인 이슈 발행, 카카오워크 알림, 심각도 기준 작업 목록화, 승인 후 착수를 연결. 수정 결과를 다시 분석 입력으로 환류하는 개선 루프 구축.

### 2. 자동화 속도와 사람의 통제력 동시 확보

- **문제**: 이슈 발행, 작업 착수, 커밋처럼 외부 상태를 바꾸는 단계의 무제한 자동화는 잘못된 변경을 빠르게 확산시킬 위험.
- **성과**: 이슈 발행과 작업 착수에 승인 게이트 적용. 분석과 초안 생성은 자동화하고, 영향이 큰 실행은 승인 뒤에만 수행하는 책임 경계 확립.

### 3. 세션이 바뀌어도 이어지는 작업 상태 관리

- **문제**: 대화형 TaskList만으로는 세션 종료 후 작업 선정 근거, 진행 상태, 검증 결과를 재구성하기 어려움.
- **성과**: 설계 문서에서 전개한 `Task_Checklist`, Git 이력, Phase 결과 문서를 단일 기준으로 운영. 작업 선정부터 완료 처리까지의 근거 보존.

### 4. AI 협업에 맞는 테스트와 커밋 규율 정립

- **문제**: 과도한 테스트와 큰 단위 커밋은 검증 비용과 변경 원인 추적 비용을 함께 높임.
- **성과**: 핵심 비즈니스 로직 중심 테스트, 관심사별 소단위 커밋, Phase 단위 검토를 규칙으로 명문화. 변경 단위별 검증과 되돌림 범위 명확화.
