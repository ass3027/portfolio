## Secuwatcher 영상 반출 솔루션

원문: 1쪽.

- 기간: 2026.04~2026.09.
- 역할: PL, 풀스택 개발, 주임.
- 주제: 다기관 CCTV 시스템 배포 표준화 및 CI/CD 구축.
- 서비스: CCTV 영상 수집, 암호화, 마스킹.
- 적용 규모: 12개 이상 지자체.
- 본인 담당: 업무 배분, 일정 조율, 배포 구조 개선 주도. 6개 지자체 내부망 서버 구축과 배포 직접 수행.
- 기술 스택 표기: Spring Boot, Docker, Vue.js.

### 문제

- 서버별 IP와 경로 설정의 소스 하드코딩.
- 배포마다 소스 수정과 현장 대응 필요.
- 실행 방식이 다른 3개 서비스.
- 최초 설치 약 4시간.

### 해결

- 프로파일 기반 설정 분리와 환경변수 주입.
- 서버별 설정 외부화.
- 3개 서비스 Docker 이미지 구성.
- 컨테이너 내부 경로 표준화.
- Docker Compose 기반 설치, 실행, 관리 자동화.
- Docker 기반 CI/CD를 통한 이미지 빌드와 개발 서버 배포 자동화.

### 성과

- 최초 설치 4시간에서 1시간, 75% 단축.
- 개발자 현장 방문 없이 기술영업 담당자의 설치 가능.
- 6개 지자체의 일관된 배포 방식 적용.
- 배포 재현성과 내부 개발 생산성 개선.

## 김포공항 LiDAR 실시간 여객 흐름 대기시간 예측

원문: 기간과 역할 1쪽, 상세 2쪽.

- 기간: 2025.08~2026.03.
- 역할: 풀스택 개발, 주임.
- 기술 스택: Spring Boot, gRPC(C++), MariaDB, Prometheus, Grafana.

### 대용량 데이터 조회 성능 개선

- **문제**: 약 2,000만 건 규모의 대기시간 및 혼잡도 조인 조회. WHERE 조건과 조인절 비효율로 응답 약 40초.
- **해결**: EXPLAIN 실행 계획 분석. 인덱스 미사용과 Full Scan 병목 확인. 조회 및 정렬 패턴에 맞는 복합 인덱스 설계와 적용.
- **성과**: 이력서 표기상 대량 데이터 조인 조회 응답 약 40초에서 1.5초.

측정 대상은 [사용자 확인 답변 Q13](answers.md#q13)과 표현 차이가 있다. 이력서의 문구를 보존하되 면접에서는 화면 결과 표시 시간이라는 확인 범위를 적용한다.

### 실시간 분석 환경과 데이터 수신 안정성 개선

- **문제**: 통계 기반 대기시간 산출 방식의 분석 한계. C++ gRPC 수신 서비스 간헐적 종료. 분산 처리 로직으로 운영 안정성 저하.
- **해결**: 핵심 메트릭 정의와 수집 범위 확장. Prometheus 및 Grafana 관측 환경 구축. Python 보고서 자동화. 메모리 누수 수정, 에러 로깅 추가, BE 공통 모듈 통합.
- **성과**: 알고리즘 분석 및 개선 시간 80% 단축. 메모리 사용량 70% 감소. 코드량 50% 감소. 수신 서비스 간헐적 종료 해소.

메모리와 코드량 수치의 사례별 배치는 [포트폴리오 12쪽 정리](portfolio-reference.md#lidar)에서 확인한다.

## FireWatcher 산불감지 시스템

원문: 2쪽.

- 기간: 2024.12~2025.08.
- 역할: AI 데이터 연계 및 영상 처리, 연구원.
- 주제: CCTV 영상 운영 장애 대응, 실시간 분석 및 전송 구조 개선.
- 규모: 13개 지역, 지역별 CCTV 100대 이상.
- 기술 스택 표기: Python, FastAPI, Kafka, Apache, Avro, FFmpeg, DeepStream.

`Apache`는 원문 기술 목록에 독립 항목으로 기재되어 있다. 해당 항목만으로 별도 사용 컴포넌트를 특정하지 않는다.

### 문제

- CCTV 영상 끊김.
- 관측 체계 부재로 장애 확인 및 조치 지연.
- DeepStream 모듈의 단일 파일 및 전역 변수 의존.

### 해결

- DeepStream 로그 에러 자동 수집.
- FastAPI 기반 영상 테스트 시스템 구축.
- FFmpeg 최적화.
- 송출 프로세스 자동 재시작과 로깅.
- 분석 모듈 클래스 분리.
- Kafka와 Avro 기반 Producer 및 Consumer 모듈 구현.

### 성과

- 영상 장애 확인 및 조치 시간 80% 단축.
- 영상 출력 안정성 85%에서 93%.
- 재사용 가능한 실시간 메타데이터 전송 구조 마련.

## Hemp 전주기 이력관리 시스템

원문: 2~3쪽.

- 기간: 2024.07~2024.09.
- 역할: BE 개발 지원, 연구원.
- 주제: 건조 프로세스 도메인 로직 설계와 CI/CD 파이프라인 개선.
- 기술 스택: GitLab CI/CD, Spring Boot, JPA, Docker, Docker Swarm.

### 문제

- 건조 상태 전이와 정책 로직의 21개 서비스 클래스 분산.
- 넓은 변경 영향 범위.
- GitLab CI/CD 배포 15~18분.

### 해결

- 상태값 기반 도메인 모델로 핵심 정책 응집.
- GitLab CI 캐시 적용.
- DEV와 PROD 중복 Docker 이미지 빌드 제거.
- GitLab Container Registry를 통한 내부 이미지 관리와 접근 통제.

### 성과

- 정책 변경 관리 대상 21개 클래스에서 1개 도메인 모델.
- CI/CD 빌드 및 배포 18분에서 6분.
