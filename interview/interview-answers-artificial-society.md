# 아티피셜소사이어티 백엔드 개발자 면접 답변

[예상 질문과 자기소개](interview-questions-artificial-society.md)

질문 문서의 번호에 맞춰 답변을 정리한다. 확인되지 않은 경험과 수치는 추가 확인 항목으로 구분한다.

## Q01

**가장 주도적으로 개발한 백엔드 프로젝트를 설명해 주세요.**

### 주 답변 초안: LiDAR

> 제가 백엔드 개선을 주도한 사례는 김포공항 LiDAR 프로젝트입니다. 실시간 여객 흐름과 대기시간을 제공하는 시스템에서 API와 SQL 병목 개선을 맡았습니다.
>
> 통계 화면의 결과 표시까지 40초대가 걸렸는데, 차트 조회 API가 엑셀 출력용 데이터까지 함께 반환하고 중복 DB 조회도 수행하고 있었습니다. 차트와 엑셀 API를 분리하고 중복 조회를 제거해 DB 조회를 4회에서 2회로 줄였습니다. SQL에서는 비교 대상 컬럼의 날짜 함수를 제거하고, 동등 조건 컬럼을 앞에, 날짜 범위 조건 컬럼을 뒤에 두도록 복합 인덱스 순서를 조정했습니다.
>
> 조건별 데이터 분포와 실행 계획을 확인하며 개선했고, 그 결과 화면에서 결과를 확인하기까지의 시간을 약 1.5초로 줄였습니다.

- **답변 근거:** [확인된 LiDAR 조회 개선 경험](answers.md#q11), [복합 인덱스 선택 근거](answers.md#q12).
- **수치 범위:** SQL 단독 실행 시간이 아닌 화면 결과 표시 시간. API와 SQL 개선의 합산 결과.
- **추가 확인:** 전체 서비스 구조와 본인의 설계 및 구현 범위.
- **추가 확인:** 가장 어려웠던 의사결정, 당시 비교한 대안과 선택 기준.
- **추가 확인:** 시간 측정 시작과 종료 시점, 반복 횟수, 비교 조건.
- **추가 확인:** 다시 만든다면 바꿀 점과 당시 제약의 연결.

어려웠던 의사결정은 실제 당시 고민을 확인한 뒤 보완한다. JD에 맞추기 위해 경험의 난도나 책임 범위를 바꾸지 않는다.

### 대체 답변 초안: Tag2Now

서비스 전체를 가장 주도적으로 만든 경험을 강조할 때 사용한다. 회사의 실무 프로젝트로 범위를 한정한 질문에는 LiDAR로 답한다.

> 개인 프로젝트 중 가장 주도적으로 개발한 서비스는 Tag2Now입니다. 철권 태그2 커뮤니티에서 활성 유저와 매칭 정보를 한눈에 확인하기 어렵다는 문제를 해결하기 위해 만들었습니다. 문제 정의부터 백엔드 구현, AWS 배포와 운영까지 직접 맡았습니다.
>
> 가장 어려웠던 부분은 공식 SDK와 게임별 호출 명세가 없는 외부 서버와 연동하는 일이었습니다. 오픈소스 서버 구현을 분석해 바이너리 프로토콜을 파악하고, Python 클라이언트를 구현한 뒤 단위 테스트와 통합 테스트로 검증했습니다.
>
> 운영 과정에서는 서비스 규모에 비해 인프라 비용과 관리 부담이 커서 ECS Fargate에서 Lightsail과 Docker Compose로 전환했습니다. 단일 서버 장애 위험을 감수하는 대신 운영 복잡도와 비용을 낮춘 선택이었습니다. 이후 실제 사용자 제보를 받아 오류와 기능을 개선했습니다.

- **답변 근거:** [Tag2Now 콘텐츠 원천](../content/01-tag2now.md).
- **JD 연결:** AWS 운영, 분석적 문제 해결, 사용자 피드백 기반 개선.
- **역량 보완:** Java와 Spring 및 관계형 DB 역량은 LiDAR나 KTX 경험으로 설명.
- **추가 확인:** 다시 만든다면 바꿀 점. 단일 서버의 백업과 복구 절차 검토는 후보이며, 실제 준비 수준 확인 후 답변 확정.

### 사례 선택과 JD 연결

이 회사에서는 LiDAR의 실무 백엔드 개선 경험을 주 답변으로 준비한다. Tag2Now는 서비스 전체를 주도한 경험을 보여주지만, 외부 서버의 바이너리 프로토콜 분석은 Spring Boot API 개발과 DB 최적화 역량을 직접 보여주는 사례로는 거리가 있다. 기술적 난도와 JD 적합성을 구분해 선택한다.

| 사례 | 강조할 역량 | 활용 질문 |
| --- | --- | --- |
| LiDAR | Spring Boot API 개선, SQL 최적화, 성능 검증 | 실무 백엔드 개발과 개선 주도 경험 |
| Tag2Now | 문제 정의부터 구현과 운영까지의 주도성, AWS 운영, 사용자 피드백 | 서비스 전체 개발과 운영 경험 |
| KTX 티켓팅 | Spring Boot와 MySQL 기반 동시성 설계, 부하 검증 | 동시성 처리와 성능 검증 경험 |

- **JD 근거:** [채용 공고](https://www.wanted.co.kr/wd/378144)의 Spring Boot REST API 개발, DB 설계와 최적화, AWS 인프라 운영, 분석적 문제 해결 요구.
- **기여 범위:** 프로젝트 전체 총괄과 본인이 주도한 백엔드 개선의 구분.
- **경험의 경계:** KTX 개인 부하 테스트와 실서비스 트래픽 운영의 구분.
- **답변 배분:** 1번은 프로젝트 맥락과 본인 역할 중심, 2번은 LiDAR 병목 분석과 성능 검증 상세.
