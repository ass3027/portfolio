# 면접 자기소개

[예상 질문](questions.md) · [답변 모음](answers.md)

Q01에 사용할 자기소개다. 아래 분량은 목표이며, 실제 말하는 속도로 연습하며 조정한다. 대표 성과 수치는 하나만 사용하고 측정 범위를 정확히 말한다.

## 30초 버전

> 안녕하세요. 약 4년간 서비스의 성능과 운영 안정성을 개선해 온 백엔드 개발자 이세진입니다. 실무에서 LiDAR 통계 화면의 조회 시간을 40초대에서 약 1.5초로 개선했고, 여러 현장에 적용할 수 있도록 배포 방식을 표준화했습니다. 문제를 로그와 지표로 확인하고, 원인을 찾아 개선 결과까지 검증하는 방식으로 일해 왔습니다.

## 1분 버전

> 안녕하세요. 약 4년간 서비스의 성능과 운영 안정성을 개선해 온 백엔드 개발자 이세진입니다. 김포공항 LiDAR 프로젝트에서는 API 구성과 SQL의 병목을 개선했고, CCTV 영상 반출 솔루션에서는 여러 현장에 적용할 수 있도록 배포 방식을 표준화했습니다. 특히 LiDAR 통계 화면에서 결과가 표시되기까지의 시간을 40초대에서 약 1.5초로 줄인 경험이 있습니다. 저는 문제를 지표로 확인하고, 원인을 찾아, 실제 운영에 도움이 되는 개선으로 연결하는 방식으로 일해 왔습니다.

## 지원 직무별 강조점

현재 목표는 Spring 백엔드, AWS 클라우드, 대용량 트래픽 처리 경험을 우선하는 회사다. KTX는 개인 프로젝트의 부하 검증 경험, LiDAR는 대용량 데이터 처리 실무, Tag2Now는 AWS 설계·운영 경험으로 설명한다. 개인 부하 테스트를 실서비스 트래픽 운영 경험으로 표현하지 않는다.

- 백엔드 성능·데이터 처리: LiDAR API·SQL 개선을 중심 사례로 사용한다. 자세한 설명은 [Q11](answers.md#q11), [Q12](answers.md#q12), [Q35](answers.md#q35)를 참고한다.
- 배포·운영: Secuwatcher 배포 표준화를 중심 사례로 사용한다. 질문 [Q07~Q10](questions.md)은 답변 준비 포인트로 참고한다.
- 지원 회사 맞춤: 공고에서 요구하는 역량과 연결되는 실제 경험을 앞에 둔다. 아직 지원 회사별 완성 문구는 작성하지 않았다.

## 사실·표현 확인

- `40초대→약 1.5초`는 SQL 단독 실행 시간이 아닌 화면의 결과 표시 시간이다.
- 대용량 보정 조인 경험은 인덱스를 깊이 다루게 된 별도 맥락이다. 화면 시간 개선의 원인으로 합쳐 말하지 않는다.
- 경력 연수는 면접 시점에 맞춰 확인한다.
