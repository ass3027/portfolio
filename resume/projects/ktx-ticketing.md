# KTX 예매 재현

- 기간: 2026.06 ~ 2026.07
- 구분: 개인 프로젝트
- 역할: 백엔드 개발 및 부하 검증

<a id="booking-concurrency"></a>

## 동시 예매 제어와 초과 판매 검증

같은 좌석에 요청이 몰릴 때 Redis 원자 선점으로 경합 요청의 DB 접근을 줄이고, MySQL의 낙관적 잠금으로 예약 상태 변경이 충돌하면 해당 요청을 실패 처리했습니다. k6에서 가상 사용자 1,000명이 같은 좌석을 요청하는 실험을 3회 진행했고, 매회 예매 성공 1건과 초과 판매 및 중복 0건을 확인했습니다. Redis 선점을 끈 비교 실험에서도 초과 판매는 발생하지 않았으며, 최종 정합성은 MySQL에서 보장했습니다.

<a id="lookup-cache"></a>

## 반복 조회 캐시와 재계산 제어

반복 조회로 같은 집계가 여러 번 실행되는 구간에 Redis 캐시를 적용했고, 캐시 만료 시 같은 키의 재계산을 한 요청만 수행하도록 single-flight를 구현했습니다. 로컬 Docker 환경의 k6 핫키 조회 실험에서 캐시 적용 전후를 비교해 응답 시간 p95가 약 8~9초에서 약 26ms로 줄어든 것을 확인했습니다.

## 기술 스택

Spring Boot, MySQL, Redis, Docker Compose, k6
